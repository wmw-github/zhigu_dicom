# 知骨影像 · 云影像另存本地（Chrome 插件）

独立的 Chrome 扩展，把云影像/内网 PACS 页面上正在看的检查**直接另存到本机磁盘**，
不依赖知骨软件是否在运行，也不唤起任何程序。与 `web_bridge/chrome-extension`
（「知骨影像 · 网页取图」）互不影响，可以同时安装。

## 与「网页取图」插件的区别

| | 网页取图（蓝色按钮） | 云影像另存本地（绿色按钮） |
|---|---|---|
| 去向 | 发给本机知骨软件打开 | 直接落盘到浏览器「下载」目录 |
| 依赖 | 知骨软件必须在运行 | 无依赖，纯浏览器完成 |
| 权限 | nativeMessaging | downloads（首次安装会多一条下载提示） |
| 钩子引擎 | inject.js | 同一份代码，独立命名空间 `__zgsave:*` |

## 安装（开发者模式加载）

1. 打开 Chrome（或 Edge / 360 极速模式等 Chromium 内核浏览器），地址栏输入 `chrome://extensions`
2. 右上角打开「开发者模式」
3. 点「加载已解压的扩展程序」，选择本目录（`chrome-extension-savelocal`）
4. 固定到工具栏即可使用

## 使用

1. 在云影像网页上打开一个检查，**翻到能看到图像的页面**（只停在检查列表时没有数据）
2. 点右下角的绿色「另存到本地」按钮
3. 进度显示在按钮上；完成后文件在 `下载/知骨另存/日期_患者名/序列名/` 下
4. 双击按钮 = 诊断面板（抓不到图时看钩子状态和请求记录）

## 落盘规则

- 位置：系统「下载」目录 / `知骨另存/` / `YYYYMMDD_HHMM_患者名/` / `序列描述_NN/`
- 文件名：优先用接口给的名字，否则取 URL 末段；扩展名按响应 Content-Type 判定（.dcm / .jpg / .png）
- 重名自动加 `(1)`，绝不覆盖旧文件
- 单击工具栏图标 = 点页面上的按钮

## 已知边界

- 内网 PACS 若校验 Referer 防盗链，浏览器扩展带不上 Referer（MV3 限制），
  这类站点会全部 403 —— 请用「网页取图」插件走知骨软件下载（软件端能带 Referer）
- 只能拿到页面加载/翻过的图 + 接口下发清单里的地址；接口只给 JPEG 预览的部署，
  存下来的就是 JPEG（诊断面板会提示「页面没提供原始文件地址」）
- 会话过期后所有地址都会失败：刷新页面重新登录后再点

## 已适配的特殊部署

- **AWS S3 预签名（临沂市兰山区人民医院等 ftimage V3 新部署）**：
  取图地址必须带 `?AWSAccessKeyId=...&Signature=...`，无签名必 403。
  v1.0.1 起三路兜底：① 浏览器真拉过的 .dcm/.jpg 地址按 rawKey 精确登记
  （保留 query 里的签名，同 rawKey 时 .dcm 优先于 jpeg 预览）；
  ② 解密后的响应里按「URL + Signature」特征直捞签名地址（含 `\/` 转义形态）；
  ③ 站点服务器对拼错路径返回 200+HTML 时按响应类型拒绝，绝不把网页存成 .dcm。
  注意：**只翻到哪张就只有哪张的签名地址，要把整个序列存全，先翻一遍图再点。**

## 与另一个插件共存

两个插件都装时，各自的钩子都会装上（inject.js 标志位一个 `__zhigu` 一个 `__zgsave`），
互不干扰、互不抢数据，只是页面会同时出现蓝绿两个按钮。
