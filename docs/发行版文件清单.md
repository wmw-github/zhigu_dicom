## 二、★ 标记的四个文件为什么必须带上

`run_env.bat` 会把**项目根目录**（`%~dp0`）也加进 `PATH`：

```bat
set PATH=%~dp0\pyenv;%~dp0\pyenv\Library\bin;%~dp0\pyenv\DLLs;%~dp0\pyenv\Lib\site-packages\PyQt5\Qt5\bin;%PATH%
set QT_PLUGIN_PATH=%~dp0\pyenv\Lib\site-packages\PyQt5\Qt5\plugins
```

> **v1.15.0 修复**：`QT_PLUGIN_PATH` 原先写的是 `pyenv\Library\plugins`
> ——**该目录不存在**，Qt 平台插件实际位于 `PyQt5\Qt5\plugins`。
> 环境变量只要被设成无效路径，Qt 就不再回退到默认位置查找平台插件，
> 症状是「进程起来了但创建窗口失败 / 界面空白」，Win7 上尤其隐蔽。
> 现在 `run_env.bat` 与 `runtime_env.py` 都会校验该目录是否真实存在。

而 `python3.dll` / `pyexpat.pyd` / `unicodedata.pyd` 这三个扩展模块 DLL
**只存在于项目根目录，pyenv 内部没有副本**。OpenCV（`cv2.pyd`）初始化时会
经由 `os.add_dll_directory()` 从这个路径解析它们。

**缺失后果**：不报 Python 异常，直接 **段错误 0xC0000005**（进程瞬间消失，
连日志都不写），表现为「双击没反应」。

> 这是本次打包实测踩到的坑：文件清单用 md5 全量校验过（69082 个文件零差异），
> 但因为这几个文件压根不在 `pyenv` 里，md5 校验看不见这个缺口。
> 任何时候重打包，务必确认根目录这四个文件在列表里。

## 三、部署自检（在新电脑上按顺序做）

### 第 1 步：确认文件齐全

双击 `install.bat` → 应提示「安装完成」并生成桌面快捷方式。
若提示找不到 `pyenv\pythonw.exe`，说明拷贝不完整，重新整目录拷贝。

### 第 2 步：命令行自检（可选但推荐）

在发行目录按住 Shift 右键 →「在此处打开 PowerShell/命令窗口」，执行：

```bat
run_env.bat
```

- 窗口不关闭、界面正常出来 → 环境 OK
- 一闪而过 → 看同目录 `run_env.err.log`

### 第 3 步：深度自检（可定位 90% 部署问题）

```bat
pyenv\python.exe -c "import cv2; print('cv2 OK')"
pyenv\python.exe -c "import onnxruntime; print('ort OK')"
pyenv\python.exe -c "import vtkmodules.all, PyQt5.QtWidgets; print('VTK/Qt OK')"
```

三条都打印 OK 才算环境完整。**任何一条段错误（窗口一闪）就是缺 DLL**，
对照上面「★ 标记的四个文件」检查。

### 第 4 步：功能自检脚本（22 项）

```bat
pyenv\python.exe _release_selfcheck.py
```

不需要连 DICOM 数据，几秒钟跑完，验证：版本号、`xray_bridge` 可导入、
**漏检反馈的四类类型与落盘/写库/删除链路**、**拖放载荷解析与放置目标**
是否在本目录可用。输出 `PASS 22 / FAIL 0` 即为正常。

> v1.7.6 曾在开发版跑通 55 项验收，却在发行版点「漏检反馈」直接闪退 ——
> 那 55 项只测了数据层（落盘、写库、极性），**从没构造过对话框**。
> 所以这个脚本特意覆盖了「界面层能否构造」和「类型字典用法」，
> 部署到新电脑后先跑它，比等到真机上才发现问题省事。

## 五、常见问题速查

| 现象 | 原因 | 处理 |
|---|---|---|
| 双击快捷方式无反应 / 一闪而过 | 缺 DLL（见第二节） | 检查★四个文件 |
| `run_env.err.log` 报找不到模块 | 文件未拷全 | 整目录重新拷贝 |
| 提示找不到 `main.py` | 目录层级错了 | 必须保持 `release\main.py` 结构 |
| AI 报「模型未加载」 | `xray\app\models\` 缺失或不全 | 确认 14 个 .onnx 都在 |
| 画面黑屏 / OpenGL 报错 | 显卡驱动 | 更新驱动，或装 OpenGL 运行库 |
| **网页导入成功、序列也能打开，但每张图都是白板** | 云端 PACS 下发的是 **JPEG-LS 无损压缩**（`1.2.840.10008.1.2.4.80`）。`vtkDICOMImageReader` 只认未压缩 + JPEG baseline，遇到 JPEG-LS 会报 `Unable to get PixelData`，几何尺寸对、像素全空；也可能是漏打包 `python-gdcm` | ① 确认 `pyenv\Lib\site-packages\_gdcm\_gdcmswig.pyd` 在位；② 跑 `_release_selfcheck.py`，看「JPEG-LS 解码器在位」是否 PASS；③ 正常流程下 `web_bridge.py` 下载后会**自动解压成未压缩**并落盘，体积涨约 4 倍属正常 |
| 路径含中文/空格后异常 | 已知限制 | 部署到 `D:\CT3D260414_release` 这类路径 |
| 点「漏检反馈 / 反馈列表」弹错（Win7 尤其明显） | 快捷方式直接跑 `pythonw.exe main.py`，**绕过了 `run_env.bat`**，进程 PATH 里没有 `pyenv\Library\bin`，`sqlite3.dll` 找不到 → `DLL load failed while importing _sqlite3` | 已由 `runtime_env.py` 自动兜底（启动时把 `pyenv\Library\bin` 补进 PATH + `os.add_dll_directory`）。若仍报错，确认 `runtime_env.py` 与 `main.py` 在同一目录 |
